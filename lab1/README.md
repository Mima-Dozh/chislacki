# Лабораторная работа №1: численные методы

Все пять методов реализованы самостоятельно на списках Python. Матричное
умножение, нормы, подстановки, вращения и отражения вычисляются собственным
кодом. NumPy импортируется только в блоках проверки результатов, сравнения
с эталоном и тестах. Вычислительные функции работают без установленного NumPy.

Исходные данные варианта 15 читаются из `data/problem1.json`–`data/problem5.json`.
Интерактивного ввода нет. Матрицы и правые части не зашиты в программах.
Точность и предел итераций для запуска заданий 3–5 также берутся из файлов.
Значения по умолчанию в сигнатурах функций предназначены для программного API.

от текущей папки оболочки. Файлы должны быть в UTF-8 и корректном JSON.

## Формат данных

| Задание | Поля |
|---|---|
| 1.1 | `a` — квадратная матрица; `b` — правая часть |
| 1.2 | `x` — строки трёх диагоналей; `y` — правая часть |
| 1.3 | `a`, `b`, `epsilon`, `max_iterations`; необязательный список `comparison_epsilons` |
| 1.4 | `a` — вещественная симметрическая матрица, `epsilon`, `max_iterations` |
| 1.5 | `a`, `epsilon`, `max_iterations` |

Пример для LU, требующий перестановки строк:

```json
{
  "a": [[0, 1], [1, 1]],
  "b": [2, 3]
}
```

Результат: `x = [1, 2]`. Матрицы задаются списком строк, правая часть —
списком чисел; LU также поддерживает несколько правых частей в виде матрицы.
Для десятичных чисел используется точка, точность можно записать как `1e-6`.
JSON не поддерживает комментарии и комплексные литералы. Комплексные данные
для LU, прогонки и QR доступны при прямом вызове Python-функций.

Чтение проверяет открытие файла, синтаксис JSON и обязательные поля.
Вычислительные методы проверяют размеры, конечность элементов и применимые
условия метода. Ошибочные данные приводят к исключению с пояснением.

## 1.1. LU-разложение с выбором опорного элемента

В столбце `k` выбирается максимальный по модулю элемент среди строк `k..n-1`.
Выбранная строка меняется местами со строкой `k`, включая уже вычисленные
множители L. Это частичный выбор опорного элемента. Разложение имеет вид:

```text
P A = L U
L y = P b
U x = y
```

`get_LU(a)` возвращает `LUFactors`: объединённую матрицу L/U, перестановку
строк и число обменов. `get_L`, `get_U`, `get_P` выделяют соответствующие
матрицы. `solve_lu(factors, b)` применяет перестановку к правой части и
выполняет две подстановки. Для обратной матрицы решается `A X = I` тем же методом.
Определитель равен `(-1)^swaps` на произведение диагональных элементов U.
Нулевой опорный элемент после выбора означает вырожденность; деление запрещается.

Выводятся A, b, P, L, U, произведения PA и LU, решение, определитель,
обратная матрица, эталон NumPy и результаты проверок. Входные данные не изменяются.

## 1.2. Метод прогонки

Для уравнения `a_i*x_(i-1) + b_i*x_i + c_i*x_(i+1) = d_i` коэффициенты
записываются в `x` как `[b,c]`, `[a,b,c]`, …, `[a,b]`. Для системы размера 1
нужна одна строка `[b]`. Правая часть хранится в `y`.

```text
P_i = -c_i / (b_i + a_i*P_(i-1))
Q_i = (d_i - a_i*Q_(i-1)) / (b_i + a_i*P_(i-1))
x_i = P_i*x_(i+1) + Q_i
```

У первой строки нет нижнего соседа, у последней — верхнего; обратная
подстановка начинается с `x_last = Q_last`. Нулевой знаменатель отклоняется.
Выводятся все пары P/Q, решение, определитель и результат проверки `A x = b`.
API: `get_P_Q(x, y)`, `get_X(p, q)`, `get_det_P(x, p)`.

## 1.3. Простые итерации и метод Зейделя

Оба метода начинают с `beta` после преобразования `A x = b` к
`x = alpha*x + beta`. Якоби использует только предыдущее приближение,
Зейдель — уже обновлённые компоненты текущего шага.

Для гарантированной апостериорной оценки используется матрица итерации T:

```text
Якоби:   T = alpha
Зейдель: T = (I-B)^-1 C, где B — строго нижняя часть alpha, C = alpha-B
q = ||T||_inf
оценка = q/(1-q) * ||x_new-x_old||_inf
```

Для Зейделя T строится прямой подстановкой, без готового обращения матриц.
Остановка происходит при оценке не больше ε. При `q < 1` используется
указанная выше оценка. Если `q >= 1`, проверяются степени T до 64-й:
при `||T^m||_inf < 1` находится верхняя оценка `||(I-T)^-1||_inf`
через сумму `I+T+...+T^(m-1)` и геометрический ряд по `T^m`.
Ошибка нового приближения ограничивается произведением этой оценки
на норму `T*(x_new-x_old)` — невязки итерационного уравнения.
Если сертификат не найден, расчёт останавливается с объяснением:
достаточное условие не подтверждено, но расходимость этим не доказана.
Оценка выводится в рамках арифметики с плавающей точкой; при крайне малой ε
ошибки округления могут стать существенными.

Выводятся заданная ε, эталон `numpy.linalg.solve`, решения, число шагов,
верхние оценки ошибок, фактические отклонения от эталона и нормы невязок.
Скорость сходимости сравнивается по числу итераций при одинаковой точности
и начальном приближении. Список точностей задаётся в `comparison_epsilons`;
без него сравнивается только основная ε.

На данных варианта 15 при ε = 1e-6 Якоби выполняет 32 шага, Зейдель — 10.
Методы возвращают `(решение, число_шагов, история_оценок)`.

## 1.4. Метод вращений Якоби

Матрица должна быть квадратной, вещественной и симметрической. На каждом
шаге выбирается наибольший по модулю внедиагональный элемент `(p,q)`.
Угол `0.5*atan2(2*a[p,q], a[q,q]-a[p,p])` определяет матрицу вращения J,
обнуляющую эту пару элементов:

```text
A_new = J^T A J
V_new = V J, начальное V = I
```

После сходимости диагональные элементы — собственные значения, столбцы V —
соответствующие собственные векторы. Они сортируются совместно.
Критерий остановки: норма Фробениуса внедиагональной части не больше ε.
В точной арифметике это также норма невязки `A V - V Λ`.

Выводятся ε, число вращений, собственные значения, каждый собственный вектор
с соответствующим значением, полная V, диагональная Λ, произведения AV и VΛ,
норма их разности и результат сравнения с ε. Дополнительно проверяется
ортогональность V и выводится история нормы внедиагональной части.
`numpy.linalg.eigvalsh` применяется только для сравнения готового результата.

Для варианта 15: 6 вращений при ε = 1e-6, невязка примерно `2.16e-7`.
API: `jacobi_eigenvalues` возвращает `(значения, V, история)`.

## 1.5. QR-разложение и собственные значения

QR-разложение вычисляется отражениями Хаусхолдера: `H = I - 2*v*v*/(v* v)`.
Операции над матрицами и скалярные произведения написаны вручную.
QR-итерации выполняются без сдвигов: активный блок раскладывается как `A = QR`,
после чего заменяется на `RQ`. Вычитание и прибавление `μI` не используются.
Отделившийся блок 1×1 даёт одно значение, блок 2×2 решается по квадратной
формуле с помощью стандартного `cmath.sqrt`, включая комплексные корни.

Точность задаёт относительный порог отделения блоков. Для плохо обусловленного
спектра этот порог не гарантирует такую же ошибку корней. Число QR-шагов ограничено.
Выводятся ε, Q, R, число шагов, собственные значения, проверки QR=A и Q*Q=I,
а также сравнение с эталоном `numpy.linalg.eigvals`.

Полный текст специальных требований к заданию 1.5 и часть списка вывода 1.1
не были переданы: соответствие отсутствующим пунктам не подтверждено.

## Проверки необходимых и достаточных условий

Все программы перед расчётом выводят условия применимости и результат
проверки. Смысл условий различается для разных методов:

| Задание | Необходимое / необходимое и достаточное условие | Дополнительное достаточное условие |
|---|---|---|
| LU с перестановками | Для единственного решения и обратной матрицы: невырожденность A; проверяются опорные элементы исключения | Строгое диагональное преобладание |
| Прогонка без перестановок | Все знаменатели прогонки ненулевые; эквивалентно ненулевым ведущим главным минорам | Строгое диагональное преобладание |
| Якоби и Зейдель | Для сходимости к единственному решению при любом начальном приближении: `rho(T) < 1` | `||T||_inf < 1`, либо `||T^m||_inf < 1`; строгое диагональное преобладание A; для Зейделя также вещественная симметрическая положительная определённость |
| Вращения Якоби | Вещественная симметричность необходима и достаточна для ортогональной диагонализации над вещественными числами | При выборе максимального внедиагонального элемента симметричность гарантирует сходимость в точной арифметике |
| QR | Квадратная конечная матрица — условие интерфейса задачи поиска спектра; QR-разложение существует и для вырожденной A | Частный проверяемый случай завершения без QR-шагов: уже отделённые блоки 1×1 и 2×2 |

Проверки относятся к указанным задачам, а не утверждают невозможность любого
другого способа решения. Например, прогонка без перестановок может сломаться
на невырожденной матрице, которую LU с перестановками успешно обработает.
Положительная определённость проверяется собственным LDLᵀ-разложением;
для Якоби она отдельно не объявляется достаточным условием.

В 1.3 матрица T строится отдельно для каждого метода. Для вывода диагностической
оценки `rho(T)` используется собственный QR из задания 1.5, без NumPy.
Если оценка отличается от 1 не более чем на `1e-7`, результат помечается как
пограничный. Это диагностический зазор, а не гарантированная ошибка QR.
Даже вдали от границы спектральная оценка не является строгим доказательством;
она не управляет остановкой метода. Если QR не смог получить оценку, выводится
«не удалось оценить», а найденное условие сжатия остаётся действительным.
Все численные проверки подвержены округлению машинной арифметики.

Для QR-итераций без сдвигов общий необходимый и достаточный
критерий сходимости заранее не реализован. Отсутствие структуры из блоков
1×1/2×2 не запрещает запуск: проверяются отделение блоков с допуском и лимит
итераций. Условия `||A|| < 1`, невырожденность или различные модули всех
собственных значений не выдаются за обязательные условия этого алгоритма.

Теоретические пояснения: [стационарные итерации, Cornell](https://www.cs.cornell.edu/courses/cs4220/2026sp/lec/2026-03-11.html),
[QR со сдвигами, Cornell](https://www.cs.cornell.edu/courses/cs6210/2025fa/lec/2025-10-29.html).

## Устройство и проверка

- `matrix_ops.py`: элементарные операции над списками, нормы и проверка входов.
- `conditions.py`: диагональное преобладание, SPD, спектральная диагностика и сертификат сжатия.
- `input_data.py`: чтение JSON и выбор файла из аргумента командной строки.
- `problem1.py`–`problem5.py`: собственные алгоритмы и демонстрация результата.
- `tests/`: проверки на NumPy как независимом эталоне и проверки интерфейса.

Результаты методов — списки Python, а не `numpy.ndarray`. Импорт не запускает
вычисления. NumPy требуется для демонстрационных проверок в `main()` и тестов.

Проверено 23 теста: разложение с перестановками, решение нескольких правых
частей, определитель и обратная матрица, прогонка, комплексные данные,
апостериорная оценка ошибки, собственные пары, ортогональность, ограничения
итераций, чтение своих файлов и обязательный вывод. Отдельный тест запускает
вычислительные функции с `python -S`, без доступа к NumPy в site-packages.

Дополнительные тесты проверяют сходимость при норме T больше единицы,
пограничный спектральный радиус, отсутствие диагонального преобладания,
сбой диагностического QR и допустимость вырожденных матриц для поиска спектра.
